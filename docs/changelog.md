# Política de changelog

## Arquivo canônico

O histórico oficial do projeto deve ser mantido em `CHANGELOG.md` na raiz do repositório.

## Padrão adotado

NeoCAD seguirá:

- [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
- [Semantic Versioning](https://semver.org/spec/v2.0.0.html)

## Categorias recomendadas

Ao registrar mudanças, priorize estas seções:

- `Added`
- `Changed`
- `Deprecated`
- `Removed`
- `Fixed`
- `Security`

## Regras de manutenção

- toda mudança funcional relevante deve atualizar o changelog;
- alterações apenas internas podem ser agrupadas quando fizer sentido;
- mudanças de documentação importantes também podem ser registradas;
- releases devem mover itens de `Unreleased` para uma versão datada.

## Objetivo

Manter um histórico claro para colaboradores, usuários e futuras distribuições desktop do NeoCAD.
