# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This is the canonical history of the project. Recommended sections, in priority
order: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`.

Maintenance rules:

- every relevant functional change updates this file;
- internal-only changes may be grouped when it makes sense;
- significant documentation changes may also be recorded;
- on release, items move from `[Unreleased]` to a dated version.

## [0.2.0] - 2026-08-31

### Added

- K2 broken down into 12 micro-tickets in `docs/tickets/k2-dxf-nativo.md`, sequenced in four blocks — format foundation, reading, writing, and arrival at the product — with the ticket that reads a block containing entities (MT-K2-05) named as the one justifying the phase, and the silent loss of unmodelled entities on save recorded as a known risk to be handled before `Salvar` can overwrite an original.
- Layout, viewport and paper-space writing in `neocad-io` (MT-KL-12), closing phase KL: the `OBJECTS` section is produced with its `LAYOUT` objects, each tab's block record is written once, and per-window layer freezing survives the round trip. The prediction that the two sibling write limitations would fall together was half wrong and is corrected here: freezing was fixed because a layer has a **name**, a stable key between the table and the window, so the writer only had to record each layer's handle; clipping was not, because group code `340` points at an **entity** and what the writer receives is a list of entities without identity — closing it needs the writer to take the document rather than a loose list. The fixed-point test from MT-K2-09 earned its keep twice over, catching the `Model` tab written twice — the writer always emits it and the reader had begun bringing it in from the file — and then a tab's block record written twice, once by the layout and once by the `BLOCKS` section; a repeated handle invalidates the file and neither would have shown up in a visual inspection. Anonymous blocks are explicitly not treated as space blocks: `*U1` and `*D15` start with an asterisk but are real content, since hatches and dimensions live in them.
- `VIEWPORT` entity reading in `neocad-io` (MT-KL-11), completing the read side of layouts: paper measurements, model view, twist and the layers frozen in each window. The viewport whose id is `1` is the sheet itself and is deliberately not turned into an entity — every paper space has one, and modelling it would put a ghost frame the size of the sheet on top of everything; being understood and deliberately unmodelled is different from being unsupported, so it does not count as a loss. The twist needed only a unit conversion, group code `51` carrying degrees against the model's radians in the same counter-clockwise orientation, which the sign test written with the model turned into verification rather than assumption. Frozen layers required the layer handle map for the same reason layouts required the block one, so the handle reader from the previous ticket was generalised rather than copied. Two absences are counted rather than silenced: clipping by a boundary entity does not resolve without an entity handle map, so the window is read rectangular and counted — a sheet with a lost clip shows more than it should — and a frozen-layer handle that resolves to nothing is counted too. A window without group code `68` is treated as on, since showing something the user can switch off beats hiding something they cannot find.
- `LAYOUT` object reading in `neocad-io` (MT-KL-10): the `OBJECTS` section now yields tab name, tab order, page setup and the link to the block, so a tab no longer has to be born from an entity citation — when the file declares it, it arrives with the paper the file states. The finding from MT-KL-01 became a design requirement of the reader: a `LAYOUT` object carries two subclasses that repeat group codes, `1` being the plot configuration's name in one and the tab's name in the other, so reading the record flattened would give the tab the configuration's name, which is usually empty — exactly what defeated a hand-written fixture earlier. The traversal follows the `100` marker and slices each subclass before interpreting it. Linking a layout to its block required reading the `BLOCK_RECORD` table, since group code `330` points at a handle and without a handle-to-name map the pointer resolves to nothing and the sheet would exist without content; only the handle and the name are read, because the rest already comes through `BLOCKS` and duplicating it would let the two readings drift. A layout whose block does not resolve is reported rather than discarded. Plot scale arrives as a ratio, numerator and denominator kept apart, since dividing on read would lose the distinction between `1:3` and the decimal that approximates it.
- Document assembly from a DXF reading (MT-KL-09), which is what had been blocked since MT-K2-06: paper-space entities had no block to live in. With the reserved-block path and the layout table in place, `build_document` now chooses each entity's destination block — model space for model entities, the tab's block for paper ones. The `410`/`67` resolution itself had existed since MT-K2-04; what was missing was the destination. A tab named by an entity but never declared is created, since the `OBJECTS` section is not consumed yet and until then it is the citation that reveals the tab — creating it is the only alternative to losing the entity. A tab whose name the model refuses does not cost the drawing either: its content goes to the default tab and the refused name is reported. Paper space consequently left the loss report: entities that used to be announced as lost now enter real tabs and are written, so the report still names the tabs — the interface needs to say the drawing lives on paper — but that is information rather than a warning of destruction. The WebAssembly facade stopped duplicating a half-assembly of its own and calls the shared one.
- Per-viewport layer freezing in `neocad-model` (MT-KL-08): each window carries the set of layers frozen in it, which is what lets the same layer appear on one sheet and not on another — without it, a plan and a detail on the same sheet would show exactly the same content. This is the first time layer visibility stops being a global property of the document: `shows_layer` combines both, and the order matters, since a window that is off shows nothing, a layer switched off or frozen in the document appears in no window at all, and per-window freezing decides the rest. Removing a layer now clears the freeze from every window, because freezing is not use: the layer can be removed while a freeze still points at it, and since identifiers are reused a new layer would inherit a dead one's freeze, hiding content nobody asked to hide for a reason invisible in the interface. Freezing does not make a layer indestructible, which has its own test. The frozen set is ordered rather than a list, so the same layer cannot be frozen twice and the file can later be written deterministically.
- `Viewport` as a modelled geometry in `neocad-model` (MT-KL-07): the paper-space window that turns a drawing into a sheet, carrying its rectangle on the paper, the view centre and height in model space, the twist and the clip. Its scale is derived rather than stored — the ratio between window height and view height — because a separate field would be a second source of truth, and a sheet whose declared scale differs from the drawn one is worse than one with no scale at all, since the error only surfaces when someone measures the plot. The twist convention is pinned by tests in both directions and by a sign test, a wrong sign rotating the sheet the wrong way without anyone noticing until plotting; mapping DXF group code `51` onto it belongs to the reading ticket. Adding a variant to `Geometry` is not a local change: it broke the exhaustive matches in the DXF writer and in the WebAssembly bridge, which in turn reaches the TypeScript contracts, and all three were updated so the bridge can represent what the model now holds. One limitation is declared rather than discovered: clipping by a boundary entity is not written, because group code `340` needs that entity's handle and the writer assigns handles as it goes without keeping an entity-to-handle map.
- `LayoutTable` in `neocad-model` (MT-KL-06), the fourth symbol table, holding each layout's tab name, associated block record, tab order and page setup. The `Model` tab exists in every table and points at `*Model_Space`, so it is the first tab rather than a separate mode, as in AutoCAD. Layout and block are created in one operation and removed in one: a layout without a block has nowhere to keep entities, a `*Paper_Space` without a layout is content the interface cannot show, and a duplicate tab name undoes the block just created rather than leaving an orphan nothing in the document can reach. Removing a layout takes its block and that block's entities with it, for the same reason removing a block already did. Two orders are offered and both are stable: alphabetical, inherited from the symbol table, and tab order with the name breaking ties, which is what the file writing will draw its determinism from. Plot scale is stored as a ratio rather than a quotient, because `1:100` is how the drafter names it and how the title block shows it, and `scale()` returns nothing for a zero denominator instead of letting an infinity into the drawing.
- `SymbolTable<T>` extracted in `neocad-model` (MT-KL-05), now the single name-indexing machine behind the layer, block and text style tables. The three had been carrying three copies of the same rule — three chances for them to drift, which was the point of the debt — and the extraction removes 73 lines net. The generic table holds the mechanics, not the policy: which record is protected, what each error means and what fits in a record stay with each table, so `SymbolError::Protected` is translated into `DefaultLayerIsProtected`, `ModelSpaceIsProtected` or `StandardStyleIsProtected` rather than flattened into one message that would tell the reader less. The `SymbolRecord` trait asks only for reading and writing the name, keeping colour, base point and text height out of the shared type. No existing test changed, which was the acceptance criterion for a refactor of stabilised code.
- Internal path for creating reserved block names in `neocad-model` (MT-KL-04): `BlockTable::create_reserved` is `pub(crate)`, so the paper-space records (`*Paper_Space`, `*Paper_Space0`) that a sheet requires can exist while no code outside the model crate can create them, as ADR 0005 demands. The public path keeps refusing the asterisk, and a `compile_fail` doctest proves the restriction is enforced by the compiler rather than merely documented. Being reserved excuses the asterisk and nothing else: a name that is only an asterisk is refused, the remainder obeys the same rules as any symbol, and duplicates are still rejected, so `*Model_Space` cannot be recreated.
- Layout enumeration in the viewer adapter (MT-KL-01): `listLayouts()` reports each layout with its tab name, associated block record, tab order, entity count and viewport count, with model space appearing as one item among them rather than as an exception. Model space is synthesised when the layout dictionary does not carry it, since a drawing without a `Model` tab still has model space and would otherwise leave the interface with no tab showing the drawing. Ordering is deterministic: model space first, then by tab order with the name breaking ties. Verifying the upstream API in a real browser — the point of the ticket, since it was previously known only from reading the package — confirmed that the dictionary, block lookup and entity counting all work, and surfaced the finding that cancelled the phase's first block. Running the upstream parser directly and reading its converter established that `dxf-json` does read the `LAYOUT` objects and does read group codes `67` and `410` on each entity, but never supplies the layout's block record id — and that the `data-model` DXF converter appends every entity to model space without ever consulting either field. Switching the active layout on the DXF path would therefore point at an empty paper-space record, so MT-KL-02 and MT-KL-03 are suspended and the sheet on screen now waits for the in-house renderer. The DWG path differs, since LibreDWG does populate `*Paper_Space`, but DWG belongs to the upstream until K6. A `two-layouts.dxf` fixture was added and is read correctly by the in-house reader, which separates the two sheets as expected.
- DXF opening switched to the in-house reader (MT-K2-12), closing phase K2. The kernel reads the bytes before and independently of the upstream, which from now on only draws; DWG keeps the old path through the extracted snapshot until K6. The `test.fail()` guarding the defect that motivated the phase is gone: `block-with-entities.dxf`, which the upstream parser cannot open at all, is now read — two entities and one block counted, document open, `Salvar` enabled. What still does not work is the drawing on screen, since rendering remains the upstream's job until K5, and the test now measures exactly that and nothing more. A file the upstream cannot open therefore remains a document here rather than leaving the application in a "nothing open" state that discarded a drawing the kernel had in hand. Two improvements surfaced only when existing tests broke: old-style polylines, which the upstream extraction counted as unsupported, are now built as real polylines, and the message shown to the user comes from the kernel's own report, which knows more.
- `Salvar` and `Salvar como...` in the `Arquivo` menu (MT-K2-11), writing through Tauri on the desktop and as a browser download otherwise. The Tauri write capability deliberately carries **no path scope**: `fs:allow-write-file` grants only the command, and access to a particular path is granted at runtime by the open and save dialogs, which register the chosen file in the filesystem scope — granting a broad scope here would give the application the power to overwrite any file the user owns. Overwriting an original when something would be lost asks for confirmation naming what stays behind, and the message after writing repeats the list; the question is only asked on the path that actually destroys, since a browser download overwrites nothing. A drawing opened from `.dwg` is written as `.dxf`, because DWG writing depends on a closed specification and is out of scope per ADR 0003, and keeping the original extension would make the file lie about its own contents.
- DXF reading and writing exposed on the WebAssembly facade (MT-K2-10): `CadSession` gains `openDxf`, `toDxf` and `saveLoss`. Only model space enters the document — paper-space entities are read, counted and reported but have nowhere to live until the layout phase — and `saveLoss` states what a write would discard from the file just opened: unmodelled entity types with counts, paper-space layouts, and blocks that are external references whose path the model does not keep. That report exists so the loss shows up before it happens, which is what lets the interface warn before `Salvar` overwrites an original, as ADR 0005 requires. The `.wasm` tripled on arrival of the format code, from 106.2 KB to 321.2 KB; a release profile for the workspace (`opt-level = "z"`, LTO, single codegen unit) brought it back to 260.5 KB. `panic = "abort"` was declined: it would save more and cost the panic messages, which are what remains for diagnosing a kernel defect inside the browser.
- Round-trip test suite closing the DXF read/write cycle (MT-K2-09), in `kernel/neocad-io/tests/round_trip.rs`. Equality is required between the first and the second write rather than against the source file: writing normalises a drawing — layers ordered, old-style polylines rewritten as lightweight ones, the mandatory space blocks added — so demanding byte equality with the original would ask for a fidelity AutoCAD itself does not deliver. What is demanded instead is a fixed point, which is what lets a drawing be version-controlled without every open producing a diff. Layers are compared by name, since `Entity` carries a `LayerId` that is a position in the arena and two reads of the same drawing create layers in different orders. The losses are written down rather than left to be discovered in a client's drawing, each with its own `perda_declarada_*` test: unmodelled entities and block references do not survive a rewrite, old-style polylines change representation though not geometry, the written header is ours rather than the source file's, and arc angles lose their last bit to the radian/degree conversion.
- DXF writing of entities and block definitions in `neocad-io` (MT-K2-08). All five modelled geometries survive a write-and-read cycle, checked one by one, and draw order is preserved because reordering changes what sits on top of what in a drawing with hatches. `$EXTMIN`/`$EXTMAX` are computed from model space only — a paper-space entity does not count, since the extents describe the drawing rather than the sheet — and are omitted entirely when there is nothing drawn, rather than declaring a rectangle nobody traced. The mandatory `*Model_Space` and `*Paper_Space` block definitions are always emitted, and a definition read with one of those names is not discarded: its entities are written inside the corresponding block so content cannot vanish over a reserved name. The `BLOCK_RECORD` table joins the written tables, since every entity belongs to a block record and that table is what declares which ones exist — it is also the structure on which ADR 0005 models layouts. Colour inheritance is written by omission, the way AutoCAD does it. The fixture that motivated the whole phase, `block-with-entities.dxf`, survives a read-write-read cycle with block and entity intact, and the second rewrite is byte-identical to the first. One loss is declared rather than discovered: the model stores angles in radians and the format writes degrees, so an arc at an arbitrary angle does not return bit-identical.
- DXF writing of header and tables in `neocad-io` (MT-K2-07), deterministic by construction: the same content produces the same bytes, and — the test that matters — two layer tables holding the same content but built in different orders produce identical files, which only holds because the table has iterated alphabetically since MT-K1-04. Determinism is pinned on three fronts: ordering (nothing walks a structure of undefined order), numbers (`formatar_real`, free of locale and of scientific notation), and identifiers (handles from a monotonic counter rather than from an address or an allocation order). `formatar_real` searches for the shortest decimal that still round-trips, up to 1074 places — stopping at 17 turned `f64::MIN_POSITIVE` into `0.0`, the very kind of silent loss this project spent days chasing in someone else's converter — and normalises `-0.0`, without which two identical drawings would write different bytes. The declared version is `AC1021` (AutoCAD 2007) rather than the functional floor of `AC1015`: up to `AC1018` DXF is not Unicode, its text meaning whatever `$DWGCODEPAGE` declares, so a layer named `Fiação` written as UTF-8 would reach a specification-following reader mangled — and in Brazilian engineering drawings accented names are the rule. The `LTYPE` and `STYLE` tables are written alongside `LAYER` with one entry each, since every layer names a linetype and every text a style, and writing only `LAYER` would leave those references dangling.
- Consolidated DXF read report and the assembly point that produces it (MT-K2-06): `read_dxf` runs the whole pipeline and returns layers, entities, block definitions and a `DxfReport` gathering everything that did not fit — unrepresented entity types with counts, layers created because an entity named one the file never defined, rejected entities and layers, unread layer group codes, sections not yet consumed along with their size, and the local traversal failures that did not stop the read. `unsupported_by_frequency()` orders what is missing, since in a real archive the weight is very uneven and guessing the order spends effort in the wrong place. Section order in the file no longer matters: sections are collected before being interpreted and `TABLES` is processed first, so entities find their layers already created — without which a file writing `ENTITIES` before `TABLES`, common from third-party tools, would create every layer by citation and lose its colour, linetype and states. A file carrying two `TABLES` sections, which concatenation produces, no longer lets the second silently overwrite the first: only the first is consumed and the other is recorded as skipped, so the loss shows up instead of happening.
- DXF block definition reading in `neocad-io` (MT-K2-05) — the ticket that justifies the phase. The fixture `block-with-entities.dxf`, which the upstream DXF parser cannot open at all, is now read correctly by the kernel, block and contained entity alike; swapping the application over to it is MT-K2-12. Block header and body are separated by position rather than by group code, since `10`/`20` means base point in the header and entity coordinates in the body while `8` appears in both — separating by code would turn one into the other. A block flagged as an external reference keeps its path, because an xref has no local content and dropping the path would make the reference vanish merely for the other file not being at hand. The `*Model_Space` and `*Paper_Space` records that real files declare in this section arrive as ordinary definitions, which is faithful both to the format and to ADR 0005's modelling of layouts as block records.
- DXF entity reading in `neocad-io` (MT-K2-04), covering `LINE`, `CIRCLE`, `ARC`, `LWPOLYLINE`, `TEXT` and the old-style polyline (`POLYLINE`/`VERTEX`/`SEQEND`), delivered in file order — which is draw order — with angles converted from the degrees the format stores to the radians the model uses. Each entity carries the space it belongs to, resolved from group code `410` (which names the tab and takes precedence) or `67` (the older flag, which only says "paper"); the tab literally named `Model` is model space, since treating it as paper would send an entire drawing to a layout that does not exist. A layer named by an entity but absent from the table is created, the way AutoCAD does when opening such a file, and the creation is reported rather than performed quietly — discarding the entity instead would lose drawing over an inconsistency the format itself tolerates. Incomplete geometry does not become a crooked entity: a circle without a radius is counted among the uninterpreted rather than passed through as radius zero, because silence there produces a wrong drawing, which is worse than a missing one.
- ADR 0005 (Accepted) making paper-space layouts a first-class kernel concept, with a new phase KL inserted between K2 and K3 — an amendment to ADR 0003 in the same spirit as the one ADR 0004 already made to K2's scope. A survey of 1,989 real drawings (excluding 407 hardware libraries, whose geometry lives entirely inside block definitions) found 70% with content in paper space: 8% with nothing at all in model space, opening blank today, and 63% with both spaces populated, opening without the sheet. Layouts are modelled the way AutoCAD models them — a block record plus metadata — reusing the block table built in K1; the space is deliberately not an entity attribute, since the owning block already states it and a parallel field would be a second source of truth. `LayoutTable` becomes the fourth symbol table and therefore triggers the `SymbolTable<T>` extraction already recorded as debt, and `Viewport` becomes an entity carrying per-viewport layer freezing.
- KL broken down into 14 micro-tickets in `docs/tickets/kl-layouts-espaco-papel.md`, ordered to put the short path before the correct one: the first block renders layouts through the upstream, which already knows how (`activeLayoutBtrId` is readable and writable), so drawings composed on paper open before the in-house model exists — at the declared cost of front-end code the later blocks rewrite.
- DXF layer table reading in `neocad-io` (MT-K2-03), turning the `LAYER` table of the `TABLES` section into a `LayerTable` with name, colour, linetype, line weight and states, while the other tables in the section are ignored. Two details that only real files teach: group code `62` carries two things at once — the palette index is its absolute value and a **negative sign means the layer is off**, so reading the sign as part of the colour would turn every switched-off layer of a real drawing into an invalid colour — and when both `62` and `420` are present the **true colour wins**, since the index is the approximation the writer leaves behind for readers that only understand the old palette. Layer `0` is updated rather than recreated, because every DXF defines it and every `LayerTable` is born with it, so creating it again would be a duplicate-name rejection on every real file. Nothing is dropped in silence: the reading carries the table, the layers the model refused along with the reason, and a per-group-code count of what the layer record contained and the model does not yet interpret.
- DXF section traversal in `neocad-io` (MT-K2-02), delivering each section with its own pairs and the framing markers stripped. Sections are delivered in file order, since the format mandates none and a third-party writer reordering them is not a reason to refuse a drawing; a section the specification does not define arrives classified as `Other` rather than aborting the read. Errors are split by whether they cost synchronisation: a failure in the pair stream ends the traversal, while a missing `ENDSEC`, an absent section name or a pair outside any section are reported and the traversal resumes at the next section — the difference between "this file cannot be read" and "this part of the file is crooked". A section left unterminated by a new `SECTION` keeps that marker pending, so reporting the error does not also cost the section that follows.
- DXF group code/value stream reader in `neocad-io` (MT-K2-01), the bottom layer of the native format support. Values are typed by the group code range — text, integer, real, boolean and hexadecimal binary — because DXF declares the type nowhere else, and a code outside the known ranges is kept as text instead of rejecting the file. Errors are named and carry the line number, since a real drawing has hundreds of thousands of them and "invalid file" locates nothing; the iterator stops after the first error rather than resynchronising, which would invent pairs. Lines that are not valid UTF-8 fall back to Windows-1252, preserving accented layer names that real files carry in the system code page.
- ADR 0002 recording the relicensing to GPL-3.0-or-later, its rationale and the discarded alternatives.
- ADR 0003 establishing the in-house, reusable CAD kernel track: a standalone Rust crate workspace under `kernel/`, compiled to WebAssembly for the frontend and linkable natively into the Tauri backend, with the `@mlightcad` upstream demoted to a replaceable parser and renderer. Staged K1 (document model and transactional undo/redo) through K9 (solid modelling with STEP/IGES), covering 2D and 3D B-rep. Copyleft dependencies are confined to the `neocad-io` crate so the kernel can be licensed independently for reuse in other projects.
- K1 broken down into 17 micro-tickets in `docs/tickets/k1-modelo-documento-transacoes.md`, with per-ticket file scope, acceptance criteria, dependency order and known risks.
- `scripts/build-test.sh` and `make dist-test` producing local test builds for both Linux (native, with `.deb`) and Windows x64 in a single run, with prerequisite diagnostics (`make dist-test-deps`) and a generated per-platform `LEIA-ME.txt`. The Windows side cross-builds through the MinGW toolchain, which needs neither `cargo-xwin`, `llvm-rc` nor administrative privileges — suitable for testing, not for distribution.
- ADR 0004 establishing a headless interface for AI agents — `neocad-cli` as the functional core and `neocad-mcp` as a thin Model Context Protocol facade — with mandatory safeguards for automated editing (never overwrite the input file without an explicit flag, `--dry-run` on every edit command, all mutations through the transactional command stack, deterministic output). Recorded as Frente 5 in the roadmap, and extending phase K2 to cover native DXF _reading_, which ADR 0003 had not scheduled because it assumed the browser-based upstream parser.
- DXF construct fixtures derived from bisecting a drawing that would not open (`e2e/dxf-constructs.e2e.ts`). Old-style `POLYLINE`/`VERTEX` and block references open and are counted as not-yet-modelled, without preventing the drawing from loading. A block definition **containing entities** is not readable by the upstream DXF parser at all — recorded as a known failure with `test.fail()`, so the suite breaks the day it starts working and the assertion can be replaced. A survey of a real archive later measured the reach: the defect hits about 11% of DXF files — the minority, but the one concentrating finished drawings with title blocks and symbols. The native DXF reading of phase K2 replaces that parser. Fixtures are synthetic.
- Architecture and API documentation rewritten for the kernel era (MT-K1-17). `docs/architecture.md` now describes the kernel as the source of truth about the drawing, with a layer diagram covering the six crates, an opening flow showing the kernel load happening after the upstream activates the document, and risks restated around the real ones — the scale of the kernel effort, the two live representations coexisting until K5/K6, and compatibility with real-world files. `docs/api.md` documents the document contracts, the single integration boundary and the kernel invariants. Phase K1 is complete: the project has an in-house document model in Rust with every drawing mutation going through a reversible transaction.
- End-to-end coverage of the drawing reaching the in-house model (MT-K1-16): opening `minimal.dxf` reports exactly the two entities and single layer the file contains, a new `with-unsupported.dxf` fixture confirms that an entity the kernel does not model yet is reported without preventing the drawing from opening, the `Editar` menu shows both actions disabled after a load, and the canvas still has real height so the kernel's arrival cannot silently regress what already worked. E2E suite grew from three tests to seven.
- `Editar` menu with `Desfazer` and `Refazer` wired to the kernel command stack (MT-K1-15). Both entries are disabled according to the real stack state and their labels name the action being undone. The route creates the kernel document, loads the drawing into it when the upstream activates a document, and re-reads the history from the kernel after every action rather than keeping a derived copy in sync by hand. Opening a drawing now reports how many entities and layers the kernel received, and how many entities it does not model yet.
- Population of the in-house model from the upstream-opened document (MT-K1-14). `buildDocumentSnapshot` reads the upstream layer table and model space and produces a snapshot, which `CadSession::load` turns into a kernel document in a single bridge crossing, resetting the undo history. Geometry is recognised by the shape of the upstream object rather than by its `type` string, whose values the upstream typings declare nowhere — arcs are matched before circles, since both carry a centre and a radius. Entities the kernel does not model yet are recorded as unsupported and counted instead of aborting the load, so a real drawing still opens.
- NeoCAD document contracts and the kernel boundary service (MT-K1-13): `CadLayer`, `CadEntity`, `CadGeometry`, `CadBounds`, `CadColor` and `CadHistoryState` in `src/lib/types/cad.ts`, with branded `CadLayerId` and `CadEntityId` so the compiler refuses to swap one for the other, mirroring the distinction the kernel makes in Rust. `src/lib/services/cad-document.ts` is the single access point to the WebAssembly kernel, loading it through a dynamic import so the `.wasm` stays out of the initial bundle. Conversion is done by pure functions that validate the kernel's output and fail loudly with the offending field path, since a malformed shape there is a kernel defect rather than untrusted input.
- WebAssembly build wired into the frontend pipeline (MT-K1-12): `scripts/build-kernel.mjs` emits the package into `src/lib/kernel/pkg` and is chained into `pnpm dev` (dev profile) and `pnpm build` (release), following the same derived-not-versioned pattern as the upstream worker sync. It reports prerequisites with actionable install commands, prints the `.wasm` size on every build, and skips recompiling when no kernel source changed — without which every `pnpm build`, including the one Playwright triggers before the E2E suite, would rebuild the whole kernel. CI gained a WebAssembly toolchain step in both the `frontend` and `e2e` jobs.
- WebAssembly facade in `neocad-wasm` (MT-K1-11): a `CadSession` bundling a document with its command stack and exposing layer and entity listings, the model-space bounding box, drawing a line, erasing an entity, toggling a layer, `undo`/`redo` and the history state. Built with `wasm-pack --target web`; the resulting `.wasm` is 107 KB. Identifiers cross the bridge as decimal strings rather than numbers, since a `u64` would surface as a `BigInt` in JavaScript for no benefit — the identifier is opaque either way. All logic sits in a JavaScript-free inner layer so the whole facade, error paths included, is testable with `cargo test` on the host.
- Drawing mutation closed behind recorded edits (MT-K1-10). `Document::edit()` returns a `DocumentEditor` that is the only public way to change entities or layer properties, and it records the inverse of every operation, so no change can happen without producing what undoes it. The direct paths became crate-private and the three that allowed unrecorded mutation (`entity_mut`, `layer_mut`, `move_entity_to_block`) were removed outright. Four `compile_fail` doctests assert that the restriction is enforced by the compiler rather than merely documented. `CommandStack::edit` makes creating a new entity undoable, which a pre-built transaction could not express since it never allocates identifiers. The `Change` primitive moved from `neocad-transaction` into `neocad-model` because crate-private visibility cannot span crates; `neocad-transaction` re-exports it and remains the owner of `Transaction` and `CommandStack`.
- Named transactions and an undo/redo command stack in `neocad-transaction` (MT-K1-09). A `Transaction` groups changes into one atomic user action: if any change fails, the earlier ones are rolled back and the document is left untouched. `CommandStack` stores, for each applied action, the transaction that undoes it — so undoing is simply applying it, which in turn yields the transaction that redoes it, making undo and redo the same operation in opposite directions. Includes a configurable history limit that drops the oldest entry, redo-branch discarding on a new commit, and empty transactions that never consume an undo step.
- Reversible change journal in `neocad-transaction` (MT-K1-08): `Change` covering entity insertion, removal and replacement plus whole-record layer edits, where `apply` returns the change that undoes it, built from the state observed at application time rather than inferred from the request. Undo therefore restores the same entity identifier and the same position in draw order, not merely an equivalent entity. Required new model primitives for exact restoration (`Arena::insert_at`, `BlockRecord::insert_entity_at`, `Document::restore_entity`) and a semantic `PartialEq` for `Document` that compares observable content while ignoring allocation residue.
- `Document` composing the entity arena with the layer, block and text style tables (MT-K1-07), and owning the invariants that span them: an entity is only accepted if its layer exists, the arena and the owning block's ordered list are kept in sync, a layer still holding entities cannot be removed, and removing a block also removes the entities it contains rather than orphaning them. Symbol tables are exposed read-only; every cross-structure change goes through a document method.
- Block and text style tables in `neocad-model` (MT-K1-06): `BlockTable` with an indestructible `*Model_Space` root block holding an ordered entity list (the order being draw order), and `TextStyleTable` with a protected `Standard` style that resolves effective text height — a fixed-height style overrides the height carried by the entity. Names beginning with `*` are rejected on creation, since that prefix is reserved for format-internal names. Name validation is now shared by all three symbol tables so their rules cannot drift apart.
- 2D drawing entities and bounding boxes (MT-K1-05): `Point2` and `Aabb` in `neocad-geometry`; `Entity` in `neocad-model` carrying layer and colour (`ByLayer`, `ByBlock` or explicit) plus a `Geometry` covering `Line`, `Circle`, `Arc`, `Polyline` and `Text`. Arc bounding boxes include every cardinal angle inside the sweep, so arcs crossing an axis are measured correctly rather than being clipped to their endpoints.
- Layer table in `neocad-model` (MT-K1-04): `LayerTable` with an opaque `LayerId` distinct from `EntityId`, layer records carrying name, ACI or true colour, linetype, line weight and off/frozen/locked state, case-insensitive name uniqueness, an indestructible layer `0`, and deterministic alphabetical iteration. Layers are referenced by identifier rather than by name, so renaming is a local operation instead of a sweep over every entity as the DXF representation would force.
- Generational entity storage in `neocad-model` (MT-K1-03): opaque `EntityId` carrying slot index plus generation, and `Arena<T>` with slot reuse, deterministic iteration by index, and stale-identifier rejection — a removed id resolves to `None` instead of silently reaching whichever value later occupied the slot. Exhausted generations retire a slot rather than reissue an already-handed-out identifier.
- CI job for the kernel workspace (MT-K1-02) running `fmt`, `check`, `clippy` and `test` on Linux and Windows, plus `make kernel-check` reproducing the same sequence locally.
- Kernel Rust workspace under `kernel/` (MT-K1-01) with the six crates defined by ADR 0003 — `neocad-geometry`, `neocad-topology`, `neocad-model`, `neocad-transaction`, `neocad-io` and `neocad-wasm` — independent from the `src-tauri/` workspace, with workspace-wide lints enforcing documented public APIs and denying `unsafe`. Crates are still empty; domain types start at MT-K1-03.
- GitHub Actions CI workflow (`.github/workflows/ci.yml`) covering type check, lint, unit tests, frontend build, Rust `fmt`/`check`/`clippy` on Linux and Windows, Playwright E2E, and secret scanning. Closes the CI gap in the project Definition of Done.
- `THIRD-PARTY-LICENSES.md` documenting the provenance and license of every runtime dependency shipped in the binaries.
- Runtime license policy in `scripts/license-policy.json`, enforced on CI by `pnpm licenses:check`, which fails when a license incompatible with GPL-3.0 enters the dependency tree or when a tracked dependency changes its terms upstream.
- `scripts/sync-workers.mjs` to derive the upstream `@mlightcad` workers from `node_modules` at build time, with a versioned `static/workers/workers.manifest.json` recording source version and SHA-256 per file.

### Changed

- **BREAKING (licensing):** the project is relicensed from MIT to **GPL-3.0-or-later**. Two runtime dependencies in the critical CAD-reading path are GPL-3.0 — `@mlightcad/libredwg-web` (LibreDWG WebAssembly build, DWG path) and `@mlightcad/dxf-json` (DXF path) — which already made the distributed binaries a combined work subject to the GPL-3.0 while the project advertised MIT. The declared license now matches the effective one. See ADR 0002.
- Upstream worker bundles are no longer committed to the repository (~9.7 MB of third-party minified code, including the GPL-3.0 LibreDWG WebAssembly build); they are generated during `pnpm dev` and `pnpm build`.

- README badges replaced with live CI status and release version; static badges that never reflected reality were removed.
- `docs/cad-panels-commands-simulation-roadmap.md` realigned to ADR 0003: the panels, commands and FEM/CFD tracks are now sequenced against the kernel phases instead of against the upstream feature set.
